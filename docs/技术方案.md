# All-Tools 技术方案（M1 实现稿）

> 对应需求文档 v2.2。本文聚焦 M1（MVP）的技术实现方案与关键设计决策，M2+ 仅列要点。

## 1. 技术栈

| 层 | 选型 | 版本基线 | 理由 |
| --- | --- | --- | --- |
| 宿主框架 | Electron | 33.x | 自带 Node 运行时与完整进程/文件能力；`<webview>` 承载工具页面；生态成熟（FR 决议见需求文档 10） |
| 构建 | electron-vite | 2.x | 主进程/预加载/渲染三端一体化构建，开发热更 |
| UI | Vue 3 + 手写 CSS | 3.5 | 轻量，M1 不引重组件库，避免骨架期依赖膨胀 |
| 语言 | TypeScript | 5.x | 跨端共享类型（common/types.ts） |
| 解压 | adm-zip | 0.5 | 纯 JS，无原生编译，用于无 git 时的 zip 下载通道 |
| 存储 | JSON 文件 + 存储接口抽象 | — | M1 决议：不引入 better-sqlite3（原生编译/分发成本），M2 可无痛替换 |

依赖国内加速：`host/.npmrc` 固化 npmmirror registry 与 electron 二进制镜像。

## 3. 关键设计

### 3.1 双形态路径解析（FR-DIST-01/02）

- 判定：`app.isPackaged`。开发态项目根 = 宿主源码仓库根；安装态 = `app.getPath('userData')`。
- **唯一出口**：`core/paths.ts` 导出 `paths.toolsDir / dataDir / manifestsDir`，业务代码禁止出现其他路径拼接。`{port}` 之外的字符串替换只允许发生在 runner 层。

### 3.2 Manifest 是唯一适配契约

- 每个工具一份 `manifests/tools/<id>.json`，字段见 `manifests/SCHEMA.md`（含 `install`/`start`/`port`/`healthCheck`/`openUrl`）。
- **端口参数化**：`start`/`install` 命令串支持 `{port}` 占位符，启动前由 lifecycle 替换为端口池分配的实际端口，并同时注入 `PORT` 环境变量。这样 vite（`-- --port`）、next（`-- -p`）、react-scripts（PORT env）三种主流形态都能表达。
- `openUrl` 支持 `{port}` 占位与路径（web-static 亦如此，统一通过内置静态服务出 http，而不是 file:// 直开——保证与 web-node 生命周期模型完全一致）。

### 3.3 生命周期状态机（FR-LC-01/02）

```
not-downloaded → downloading → installing(仅 web-node) → ready
ready → starting → running → stopped → starting ...
任意态 → error（失败），error → ready（重试）
```

- 健康检查：轮询 `http://127.0.0.1:{port}{path}`，500ms 间隔，默认 60s 超时（manifest 可覆盖）；HTTP 状态 <500 即视为就绪（兼容 401/302）。
- 宿主启动时把持久化中遗留的 `running/starting` 归位为 `stopped`（进程不可能跨宿主存活）。
- 宿主退出（`will-quit`）逐个 stop；Windows 下子进程用 `taskkill /PID x /T /F` 终止整棵进程树（Job Object 级联放 M2 加固）。

### 3.4 端口池（FR-LC-03）

- 预探测：`net.createServer` 试绑；manifest 默认端口可用则优先用，被占则从 41000 向上找空闲。
- 分配表存内存 + 持久化到 installed 记录，宿主内多工具并行互不冲突。

### 3.5 下载双通道（FR-DL-01/02/03）

- 优先 `git clone --depth 1 --progress`（解析 stderr 进度推送到渲染层）；无 git 时走 `codeload.github.com/{owner}/{repo}/zip/refs/heads/{main|master}`，adm-zip 解压到临时目录再原子改名落位。
- 取消/失败清理半成品目录；下载地址组装支持后续镜像前缀配置（M1 预留 setting 字段，不做 UI）。

### 3.6 web-static Runner

宿主内置极简静态文件服务（`http` + mime 表 + index.html 回退），监听 `127.0.0.1:{port}`，使静态工具与 web-node 工具共享同一套"启动-健康检查-打开-停止"流程，渲染层零特判。

### 3.7 IPC 契约（preload 暴露 `window.allTools`）

| 通道 | 方向 | 说明 |
| --- | --- | --- |
| `catalog:list` | invoke | 全量清单 + 安装状态合并视图 |
| `env:info` | invoke | node/npm/git 检测结果 |
| `tool:acquire` | invoke | 下载（+安装）流程，过程经事件推送 |
| `tool:start` / `tool:stop` / `tool:remove` | invoke | 启动返回 openUrl；remove 前置 stop |
| `tool:detail` | invoke | manifest + installed + 日志快照 |
| `prefs:get/set` | invoke | 收藏、最近使用 |
| `tool-state`（事件） | 主→渲染 | 状态变更（id/state/port） |
| `tool-log`（事件） | 主→渲染 | 安装/启动/运行日志增量 |
| `acquire-progress`（事件） | 主→渲染 | 下载进度 |

### 3.8 安全基线（FR-SEC）

- `contextIsolation: true`、`nodeIntegration: false`，preload 仅暴露白名单 API。
- `webviewTag: true` 仅用于承载本地工具页面；新窗口统一转交系统浏览器（`setWindowOpenHandler`）。
- 命令来源仅限 Manifest 声明（M1 预置清单随仓库评审），无用户输入拼接到 shell 命令（除 `{port}` 数字替换）。

## 4. M1 有意简化（与需求的差距台账）

| 简化点 | 理由 | 补齐计划 |
| --- | --- | --- |
| 存储 JSON 而非 SQLite | 决议见需求文档 10 | M2 抽象已就位，替换实现即可 |
| web-node 用系统 Node 而非宿主内置 | 开发态机器必有 Node；sidecar 打包属 M2 分发议题 | M2 内嵌 LTS |
| 首屏预置 10 个固定清单，无目录采集 | 先把端到端闭环做实 | M2 GitHub 采集 + 远程 Manifest 更新 |
| 手动添加仓库向导未做 | UI 工作量大 | M2（FR-DL-05） |
| 收藏/最近使用持久化但无复杂排序 | 闭环优先 | M2 |
| 进程清理用 taskkill /T | 简单可靠 | M2 评估 Job Object |

## 6. 本地开发

```bash
cd host
npm install          # .npmrc 已配置国内镜像
npm run dev          # 启动宿主（开发态：工具落在仓库 tools/，数据落 data/）
npm run build        # 三端构建校验
```

验收对照需求文档 §9：获取 2048（web-static，零依赖秒开）→ 窗口内打开；获取 excalidraw（web-node，走 npm install）→ 启动 → 窗口内使用 → 停止无残留进程。
